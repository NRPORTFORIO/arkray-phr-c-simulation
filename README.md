# 医療用PHR（健康管理）アプリケーション・コアロジックシミュレータ

![Wandboxでの動作検証画面](ここに画像のファイル名を書く)

## 概要
医療用アプリ開発企業（アークレイグループ）への応募にあたり、自社开发されている糖尿病患者向けPHRアプリの「血糖値・バイタル・歩数管理機能」のコアロジックを、C言語を用いて自主制作・再現したシミュレーションプログラムです。

実務未経験からの挑戦ですが、御社の10ヶ月の研修体制を通じて「爆速で仕様を理解し、即戦力化できる地頭と技術への熱意」を証明するために作成しました。

## 技術的なアプローチと実装の意図

未経験だからこそ、単に動くコードを書くのではなく、実務で扱われるデータの設計思想やメモリ効率、安全性を強く意識して実装しました。

### 1. 構造体（struct）によるデータ集約
患者の日々のアナログデータ（血糖値：int、血圧：int、歩数：int、日付：char、アラート有無：bool）はすべてデータ型が異なります。これらを個別の変数ではなく、1つの構造体 `HealthRecord` として集約・カプセル化することで、実際のアプリ開発（C#のクラス設計など）に近いオブジェクト指向的なデータ管理の設計にしました。

### 2. 構造体ポインタ（アドレス参照）によるメモリ最適化と関数設計
大量のバイタルデータを扱う医療アプリにおいて、値渡し（データの丸ごとコピー）はメモリを圧迫し処理速度を低下させます。そのため、本プログラムの関数（データ登録・アラートチェック・サマリー計算など）は、すべて構造体ポインタ（`HealthRecord *record`）を用いてアドレス参照で処理する設計に徹底し、メモリ負荷の極小化と高速化を意識しました。

### 3. ガイドラインを意識した自動アラート制御（論理回路の応用）
工業高校・大学で学んだ論理回路（条件分岐）の知識を活かし、データ登録時に自動で医療ガイドライン（血糖値140mg/dL以上、または最高血圧130mmHg以上）を判定し、`is_alert` フラグを真（true）にする判定ロジックを組み込みました。

### 4. constポインタによるデータの安全性確保
データ一覧を表示する関数（`display_all_records`）など、値を書き換える必要がない処理には `const HealthRecord *records` と読み取り専用のポインタにすることで、実務で最も重要視される「データの誤書き換え（バグ）の防止」を考慮した安全性の高いコードを書きました。
